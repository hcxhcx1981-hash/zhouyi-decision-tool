# 八字分钟边界语义冻结补丁 V0.1.1

## 决策范围

本补丁只解决出生时间精确到分钟时，月界节 `instant_utc` 与输入分钟如何比较的语义冲突。它不修改四柱其他规则、不修改正式节气时刻、不接入应用页面，也不解除页面的 `NOT_IMPLEMENTED`。

## 冻结裁决

用户输入的当地民用时间 `HH:mm` 表示半开区间：

```text
[当地 HH:mm:00, 当地下一分钟)
```

该区间必须先由后续正式时区适配器转换到同一 UTC 时间轴，再直接与正式节气记录的 `instant_utc` 比较。立春或十二个月界节令瞬间落入区间时，结果必须为：

```text
BLOCKED + SOLAR_TERM_SAME_MINUTE_AMBIGUOUS
```

禁止把正式 `instant_utc` 四舍五入、向上取整或改写为历书展示分钟后再决定前后。`BOUNDARY_SENSITIVE` 只用于能够唯一判定且距离边界不超过两分钟的结果，不能代替阻断。

## 回归案例

V0.1.1 保留原 63 个 `case_id` 和输入，只修正上述 6 个期望；新增 7 个匿名边界案例，总数为 70。新增案例补齐小寒、清明、立夏、小暑、立秋、白露、寒露，使十二个月界节各有一个“输入分钟包含正式瞬间”的阻断案例。

验收口径：

- V0.1.0 冲突：6/6 被明确修正。
- V0.1.1 案例：70/70 结构与边界语义通过。
- 十二个月界节同分钟阻断：12/12。
- 正式节气记录：3192/3192 继续复用 V0.1.0，`instant_utc` 修改数为 0。
