# 周易决策工具产品架构 V0.1

状态：`PHASE_2_PRODUCT_SKELETON`。本文件冻结产品骨架与数据边界，不冻结或实现八字、纳甲及运势算法。

## 1. 产品定位

本项目是本地优先、手机优先的双模块 H5，用于传统文化学习、规则化排盘与决策参考。产品把“用户输入”“确定性规则”“证据原文”“解释输出”分层，任何尚无冻结来源的能力必须显式阻断，不得用模拟结果补位。

## 2. 双模块结构

```text
/
├─ /bazi/    生辰八字：出生资料录入与未来四柱协议
└─ /liuyao/  六爻问事：问题输入、逐爻录入、卦象与原文证据
```

首页只负责模块选择、能力状态和使用边界，不承载完整排盘工作台。两个子模块拥有独立页面、状态和数据协议，共享移动视觉、站点 metadata 与 Footer。

## 3. 当前已实现能力

- 双模块移动端导航与静态路由。
- 八字出生资料表单、输入校验和 `NOT_IMPLEMENTED` 阻断结果。
- 六爻问题标题、详细问题、时间范围与六次自下而上逐爻录入。
- 六爻本卦、之卦、动爻、0—6 动爻取辞路由和规则轨迹。
- 三爻动自动主次阻断。
- 乾、坤、屯的冻结古籍原文证据和未收录卦提示。
- 本地静态导出、发布审计与隐私边界。

## 4. 八字待实现能力

- 公历/农历转换与闰月处理。
- 节气换月、时区与真太阳时。
- 年柱、月柱、日柱、时柱的确定性排盘。
- 日主、五行、十神、大运、流年及解释规则。
- 性格、事业、财运、关系、健康和阶段运势输出。

这些能力在规则来源冻结和回归样例建立前均不得进入正式结果。当前农历不可提交，出生地只保留文本且不参与计算。

## 5. 六爻待实现能力

- 纳甲、世爻、应爻。
- 六亲、六神、旺衰、生克、冲合。
- 用神选择及来源可追溯的判断规则。
- 进展、阻碍与结局判断。

当前只允许人工逐爻输入 `6 / 7 / 8 / 9`，不提供随机、铜钱模拟、时间起卦或 AI 代选。

## 6. 数据协议

- 八字协议：`src/lib/bazi/types.ts`。`BaziBirthInput` 描述历法、日期、时间精度、性别和出生地；`BaziAnalysisResult` 用 `NOT_IMPLEMENTED` 与 `chart: null` 表示规则未完成。
- 六爻协议：`src/lib/liuyao/types.ts`。`LiuyaoCastInput` 固定问题信息和六个自下而上的爻值；`LiuyaoAdvancedReading` 的未实现字段必须为 `null`。
- fixture 只允许用于测试，不得进入正式页面或当作命理结果。

## 7. 确定性规则层

确定性规则层包含 `src/lib/divination.ts`、`data/frozen/zhouyi_divination_rules_v0.1.json` 和相关冻结案例。运行时规则继续以冻结 JSON 为唯一来源；TypeScript 只负责通用计算、类型校验和按 `rule_id` 执行。八字和纳甲规则当前不存在于确定性层。

## 8. 解释层

解释层只能消费确定性计算结果和已接入证据，不得反向改变排盘。当前展示卦辞、彖传、爻辞、小象、资料缺口和决策反思；不自动融合注家、不调用模型、不把推断写成必然结论。八字解释层与六爻进阶解释层尚未实现。

## 9. UI 层

UI 层由首页、八字表单、六爻问事工作台和结果证据组件组成。交互遵守手机优先、输入字号不低于 16px、触控高度不低于 44px、safe-area、无横向滚动。绿色只表示可用/通过，橙色表示待完成/提醒，红色表示阻断。

## 10. 本地数据与隐私边界

- 出生资料和问事内容只存在于当前页面内存，不上传、不联网。
- 不写入数据库、localStorage、Cookie 或历史记录。
- 分享信息不得包含问事文本、六爻数字、卦象结果或古籍长文。
- 不读取真实环境文件，不写入真实出生信息和问事样例。

## 11. 禁止伪造清单

- 模拟四柱、日主、五行、十神、大运或流年。
- 未经来源冻结的农历转换、节气换月和真太阳时。
- 纳甲、世应、六亲、六神、用神、旺衰、生克、冲合。
- 事情成败、进展、阻碍或结局预测。
- 其余 61 卦原文、随机起卦、铜钱模拟或 AI 代选。
- “必然发生”“精准预测”“改命”“100%准确”“保证成事”“凶吉已定”等承诺。
